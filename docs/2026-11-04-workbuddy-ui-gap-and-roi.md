# UI 与 WorkBuddy 差距及 ROI 路线（2026-11-04）

- 对照对象：WorkBuddy 官方文档（任务管理 / 任务对话 / 结果查看 / 右侧边栏 / 专家中心 / 技能 / 自动化，2026-11 访问）
- 对照范围：`products/conatus_work/ui/` 与 `products/conatus_work/shell/`
- 结论：骨架（任务 → 对话 → 产物/变更 → 撤销）已对齐；差距集中在任务管理、对话输入、结果区完整度，
  再往上是生态层与桌面发布工程。

## 一、已对齐或领先

| 能力 | 我们的状态 |
|---|---|
| 三栏工作台（任务 / 过程 / 产物·变更·检查点） | 已有 |
| 任务状态、运行中停止、失败重试 | 已有 |
| 时间线、工具归组、关键事件过滤、reasoning 折叠 | 已有 |
| 产物预览：MD / HTML / 图片 / PDF / DOCX / XLSX / CSV / JSON | 已有 |
| 变更摘要、逐文件 diff、撤销/重做、失败逐文件列表 | 已有 |

| 可确定性回放的 fixture 与边界用例 | 已有 |

## 二、差距清单（按严重度）

### P0：每天都会碰到

| 能力 | WorkBuddy | 我们 | 归属 |
|---|---|---|---|
| 自由任务输入 | 一句话描述直接开跑 | 只能选预置任务卡 | UI + 逻辑 |
| 继续对话 | 已完成/失败/中断后都能继续 | UI 已接线，宿主 `message.send` 未实现 | 逻辑 |
| 附件上下文 | 上传 / 拖拽 / 粘贴截图 | 无附件入口 | UI + 逻辑 |
| `@` 引用 / `/` 调技能 | 输入框内直接使用 | 无 | UI + 逻辑 |
| 任务搜索 | 顶部搜索面板 | 无 | UI |
| 时间筛选 | 今天 / 7 天 / 30 天 | 只有状态筛选 | UI |
| 任务管理 | 置顶、归档、重命名、删除、批量、打开文件夹、分享 | 只有切换任务 | UI + 逻辑 |
| 工作空间 | 任务 / 空间两级，可新建、重命名、移除 | 只有选择工作区 | UI + 逻辑 |
| 计划展示 | 规划阶段与执行步骤 | `plan` 已有数据但未渲染 | UI（低成本） |
| 并行任务 | 可同时推进多个任务 | UI 已支持；撤销语义仍是一任务一轮 | 逻辑 |

### P3：桌面壳与发布

- WorkBuddy：Windows + macOS 安装包、菜单、通知、托盘/任务栏、深链、自动更新。
- 我们：macOS 单窗口；无通知、托盘、菜单项、深链、更新检查、签名公证、Windows。
- 已有：loopback + token、CSP、文件选择器、WebView 桥、打包脚本。

### P4：明确不跟

企业账号、云同步、团队协作、公开分享链接、技能/专家市场运营、通用“什么都能做”的承诺、
品牌化视觉、动效、i18n。

## 四、需要逻辑侧补的命令（UI 已按此预留）

- `message.send` / `approval.respond`：见 `2026-11-04-ui-shell-handoff.md`。
- `task.rename` `{ runId, title }` → `RunSummary`。
- `task.archive` / `task.delete` `{ runId }` → `{}`。
- `task.pin` 可先留在 UI 本地（`localStorage`），不必进宿主。
- `fs.list` `{ runId, path }` → `{ entries: [{ name, path, kind, bytes?, modifiedAt? }] }`。
- `fs.read` `{ runId, path }` → `{ content, truncated, encoding }`（与 `artifact.read` 同形）。
- `message.send` 增加可选 `attachments: [{ name, path, mime, bytes? }]`，或单独的 `file.upload`。
- `task.share` → `{ url }`（若做分享；本地优先定位可先不做）。
