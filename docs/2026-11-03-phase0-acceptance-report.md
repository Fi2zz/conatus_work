## 五、失败与救场归因

22 次失败尝试，**0 次由任务难度导致**：

| 根因 | 次数 | 表现 | 处置 |
|---|---:|---|---|
| 产物规则过严（`maxChars` 太紧、英文卡硬加 `contains`） | 2 | v02/v04 判 `tooLong` / `missingText` | 规则校准后重跑通过 |
| 未确认提示被误解为「不许写任何文件」 | 4 | csv v02–v05 产物缺失 | 改写未确认文案为「可读、可写 out/」 |
| 缺少 `--yes` 放行通道 | 1 | organize 只产出 dry-run | 增加 `--yes`，写进用户回合 |
| 产物结构未约定 | 2 | `changes.json` 换名字、缺 sha256 | 把 schema 写进任务卡 + 结构化校验器 |
| `move` 不返回 sha256 | 2 | 模型只能写 `null` | `move` 返回并写进工具文本 |
| 图片附件打挂文本模型 | 1 | 上游 400 `unsupported image format` | `conatus_fs_tools.attachImages=false` |
| 卡片时长上限过紧 | 3 | 12 分钟超时（v02、organize v06、csv v09） | 提到 20 分钟；提示「图表一次写完」 |
| 上游瞬时不可用 | 2 | `Endpoint is unavailable` | 直接重跑 |
| 模型反复润色 SVG | 2 | 耗满 12 分钟 | 提示 + 提上限 |
| 冒烟排障（无 Key / 错端点） | 3 | `llm` 失败 | 排障用，非任务 |
| 外部中断 | 1 | 进程被杀，记录 `aborted` | 重跑 |

**人工救场（改产物 / 补步骤）：0 次。**

> 口径警告：`rescuedBy=rerun:29` 是本次「全量重跑」造成的——同一 `taskId` 在重置后的
> 工作区里再跑一次，`rerunOf` 会自动记为上一次运行。**在一次刻意的全量重跑里，
> 救场率没有意义**，只有当批次内首次运行时它才反映真实返工。要拿干净救场率，
> 需要清空 `var/runs` 后跑一轮。

## 五之二、跨模型验证（GLM-5.3-Flash）

同一套任务卡与夹具，换成 `opencode-go/glm-5.3-flash`（$0.15 / $0.50 每百万 token）：

| 任务 | 结果 | 耗时 | 输入 token | 输出 token | 成本 |
|---|---|---:|---:|---:|---:|
| research-v03 | succeeded | 2.7 min | 753,902 | 7,563 | $0.036 |
| research-v07 | **failed / timeout** | 20.0 min | 320,242 | 606 | $0.014 |
| csv-v04 | succeeded | 2.1 min | 19,805 | 8,735 | $0.006 |
| csv-v10 | succeeded | 3.0 min | 24,332 | 12,606 | $0.008 |
| organize-v05 | succeeded | 0.8 min | 20,553 | 2,166 | $0.003 |
| organize-v07 | succeeded | 0.5 min | 14,724 | 1,216 | $0.002 |

**5/6 成功，总成本 $0.069**（DeepSeek 单任务均价的约 1/10）。

结论：

- **契约可移植**：`RootedFileSystem`、`move` 返回 sha256、`changes-manifest` /
  `sources-json` 校验器在 GLM 上全部适用，没有出现「只有 DeepSeek 能过」的情况。
- **差异出现在长任务**：GLM 在 `research-v07`（英文调研）上耗时 20 分钟只产出 606 个
  输出 token，最终超时。怀疑是搜索/抓取循环，而非产物问题。
- **成本差异巨大**：同样的中文调研任务，GLM 用 754K 输入完成，DeepSeek 需要 1.2M。

## 七、已知缺口

1. ~~**超时/取消时用量丢失**~~：已修。`UsageMeter` 包在 provider 外层，任何完成的调用都会
   计入；超时 / 异常路径改为读计量器累计值。回归测试覆盖「模型中途抛错仍记录已完成调用的用量」。
   仍未覆盖的是「取消发生在调用进行中」的瞬间用量——那部分本来就无从取得。
2. **超时路径无自动化测试**：`AgentCancel` + `Timer` 仅做代码审查。
3. ~~**成本未启用**~~：已配置单价并实测生效（`costUsd` 精确到 1e-6）；
   `maxCostUsd` 的判定逻辑有单元级用例，但尚未在真实长任务上触发过。
4. **`--fixture` 无 CLI 参数测试**：只覆盖了 `resolveWorkspaceRoot` 纯函数层。
5. **空目录不被检查点恢复**：影子 git 不跟踪空目录，撤销后 `out/` 会消失，靠下一次
   `prepareWorkspace` 重建。
6. **单机单模型验证**：只跑了 `deepseek-v4.1-flash`，跨模型的任务成功率仍是未知数。
   已补 GLM-5.3-Flash 的 6 任务验证（见五之二），结论是契约可移植、长任务稳定性有差异。
7. ~~**超时后进程被遗留连接吊住**~~：已修。根因是 `conatus_search` 的 provider / fetcher
   各自新建 `http.Client` 且从不关闭；现在由 `provideSearch` / `provideWebTools` 统一持有
   并随上下文释放，CLI 另以 `exit()` 收口。超时路径实测 3 秒内退出（修复前可挂十几分钟）。
